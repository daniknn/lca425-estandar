Antes de empezar

Elige tu vía

Las reglas son las mismas en las dos. Lo que cambia es quién hace los pasos de GitHub por ti. Si no sabes qué plan de Claude tienes, contesta el censo y Daria te dice cuál usar.

Vía A · Claude Code

Con plan Pro o Max de Claude.

Claude crea la rama, escribe el archivo y abre el PR. Además, el plugin del curso frena a tiempo lo que no debe pasar, como subir directo a main.

La primera vez, en la Terminal:

claude update

Luego, dentro de Claude Code:

/plugin marketplace add daniknn/lca425-estandar
/plugin install lca425@lca425

Al inicio de cada clase:

/plugin marketplace update lca425
/reload-plugins

Vía B · claude.ai y GitHub web

Con cualquier plan de Claude, incluso el gratis.

Usas las tarjetas del curso: cada una es un prompt que pegas en claude.ai. Te devuelve el texto y tú lo pegas en GitHub desde el navegador.

El gate revisa tu PR igual que en la vía A. Lo que no tienes es el aviso previo del plugin, así que pon atención en un punto: al guardar en GitHub, elige siempre "Create a new branch".

Clase 12

Tu primer PR: el brief

Un PR es una propuesta de cambio. La haces en una rama, el gate la revisa y, si sale en verde, la mergeas. El brief responde dos preguntas antes de generar cualquier cosa: qué tiene que lograr la pieza y en quién.

Antes: crea tu repo (una sola vez)

  1. Abre la plantilla del proyecto y pulsa Use this template → Create a new repository.
  2. Nómbralo lca425-tu-usuario y elige Private.
  3. En Settings → Collaborators, invita a daniknn para que Daria vea y revise tu trabajo.

Con Claude Code

  1. Abre tu repo en Claude Code.
  2. Escribe /lca425:brief y contesta una pregunta a la vez.
  3. Cuando te pregunte qué hiciste tú, contesta con tus palabras. Claude no lo escribe por ti.
  4. Claude abre el PR. Espera la marca verde y mergea.

Con claude.ai y GitHub web

  1. Pega la tarjeta brief en claude.ai y contesta.
  2. En GitHub abre 00_brief.md, pulsa el lápiz y pega el texto.
  3. Guarda con "Create a new branch" y abre el PR.
  4. Llena las tres secciones del PR, espera la marca verde y mergea.

El brief es nivel Aviso: lo mergeas tú con el gate en verde y Daria lo revisa en la clase siguiente. Paso a paso completo: cómo trabajar.

Cada cambio tiene un nivel

Los cuatro niveles

Lo declaras en cada PR. Si dudas entre dos niveles, elige el más alto.

Libre

Lo mergeas tú con el gate en verde.

Notas, prompts de prueba.

Aviso

Lo mergeas tú; Daria lo revisa en la clase siguiente.

Brief, borrador de guion, shotlist, clips de prueba.

Revisión

Daria aprueba el PR antes del merge.

Entregas que se califican, material de terceros.

Permiso

Abres un issue [Permiso] antes de empezar.

Temas sensibles, pasarte del tope de créditos, publicar fuera del aula.

Cuando algo se frena

Un bloqueo te dice qué hacer

El gate, el plugin y Claude te avisan siempre con el mismo formato de cuatro partes. Ejemplo real: intentaste subir directo a main.

✋ Qué pasó
Intentaste subir cambios directo a main.
Por qué
Cada cambio entra por un PR para que el gate lo revise y se pueda deshacer.
Qué puedes hacer
1. Crear una rama y abrir un PR. 2. Pedirle a Claude que lo haga por ti. 3. Preguntarle a Daria si no estás segura o seguro.
Cómo destrabar
Elige la opción 1 o la 2. No busques otro comando para lograr lo mismo.

Si ninguna opción te sirve, abre un issue y copia el mensaje del bloqueo. Más en cuando algo se bloquea.

Sin excepción

Cuatro cosas que nunca cambian

  • La media va a Drive. Videos, audios y proyectos de edición nunca entran al repo; en clip_url pegas el link. Si ya subiste uno por error: qué hacer.
  • Das crédito al material que no hiciste. Música, imágenes, logos o voces de otras personas llevan su crédito en el PR.
  • Declaras qué hizo la IA y qué hiciste tú. En cada PR. Se evalúa tu criterio.
  • Sin llaves ni contraseñas en el repo. Si se te coló una, avisa a Daria de inmediato: hay que revocarla, borrarla no basta.
